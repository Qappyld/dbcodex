# Inventaire fonctionnel de dbcodex

## Cadre de la revue

- **Date de revue :** 25 septembre 2026.
- **Périmètre :** documentation officielle actuelle de dbdiagram et de DBML, y compris les notes de version publiées jusqu'au 23 septembre 2026.
- **Lecture des statuts :** « non documenté » signifie qu'aucune confirmation n'a été trouvée dans les sources officielles revues ; ce n'est pas une preuve d'absence dans le produit.
- **Échelle de complexité :** faible, moyenne, élevée ou très élevée pour une implémentation locale dans Codex.
- **Contrainte transversale :** toute écriture future devra préserver sans perte la syntaxe DBML non rendue graphiquement.

## Synthèse

La V1 déjà acquise est un outil local-first dans Codex : ouverture d'un fichier `.dbml`, validation, diagramme interactif, déplacement des tables, zoom/navigation, recherche/filtres, vues nommées, vue permanente `View All`, exports PNG et SVG. La recommandation générale est de garder la première version centrée sur la lecture et l'exploration fiables, avec un modèle interne séparé du texte source et une stratégie explicite de préservation sans perte avant d'autoriser l'écriture.

Le candidat naturel pour le parsing est le package officiel [`@dbml/core`](https://dbml.dbdiagram.io/js-module/core/). Il parse DBML et plusieurs dialectes SQL, exporte DBML/SQL, fonctionne dans Node ou le navigateur, et propose une API multi-fichiers incrémentale. La documentation recommande `dbmlv2`; l'ancien mode `dbml` est déprécié. Le dépôt officiel [`holistics/dbml`](https://github.com/holistics/dbml) est sous licence Apache-2.0. Ces éléments rendent l'option prometteuse, mais un prototype de compatibilité et de round-trip reste obligatoire avant le choix architectural.

## Points à vérifier avant l'architecture

1. Tester `@dbml/core` en mode `dbmlv2` sur toutes les syntaxes publiées en 2026, notamment `Dep`, `Metadata`, `DiagramView`, `Records`, relations optionnelles et modules.
2. Mesurer la qualité des diagnostics, la disponibilité de positions/source maps et la possibilité d'un round-trip réellement sans perte.
3. Confirmer la compatibilité du runtime du plugin Codex avec le package officiel et ses dépendances.
4. Comparer au moins deux moteurs de diagramme et trois formes d'intégration Codex avant de choisir.
5. Définir le format de persistance des positions/vues sans altérer les fichiers utilisateur ni créer de conflits Git excessifs.
